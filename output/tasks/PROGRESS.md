# 進捗引き継ぎノート — Arin(ライト・マルチターミナル)

> **用途**: 複数セッション(複数コンテキストウィンドウ)にまたがる作業の引き継ぎ。
> SessionStart フックが冒頭を自動注入するので、次のセッションは推測なしで再開できる。
>
> **原則**: 1 セッション 1 タスク / 着手前にスモークテスト / 終了時はテスト緑 + コミット + 本ファイル更新。
> 機能リストの行は **`passes` 列を更新するだけ**。行の削除・受け入れ条件の書き換えは禁止
> (未実装の機能が「無かったこと」になるため)。
>
> タスクの中身は `output/tasks/PLAN_multi-terminal.md`。ID(T1〜T62)は同じ。
> M2 以降(T28〜)は粗い分解。各マイルストーンの最初のタスクで分解し直し、行を**追加**する。

- **T15 で分かったこと**: `portable-pty` の `CommandBuilder::new` では `argv[0]` を `-zsh` にできないので、`new_default_prog()` を使い `SHELL` で起動するシェルを決める。親の環境変数は `env_clear()` で捨てる。シェルが実行できない・cwd がフォルダでないときは、`portable-pty` が黙って別の値に切り替えるので、起動の前に確かめてエラーにする。`kill` は SIGHUP のあと最大でおよそ 200ms 待って SIGKILL。既定のシェルは `dscl`、言語設定は `defaults` で引く(`unsafe` と新しい依存なし)。新しく入ったクレートに公開 2 週間未満のものは無い
- **T17 で決めたこと**: コマンドは `connect_terminal`・`write_terminal`・`ack_terminal_output`・`resize_terminal`。出力は生のバイト列でチャネルに流す。状態が変わると `app-snapshot` イベントで写し全体を送る。`AppSnapshot` に `terminals` を足した(版は 1 のまま)。M1 のターミナルは ID `terminal-1`、cwd はホーム【仮定】。流量制御の仮の値は 上限 512 KiB・下限 128 KiB、まとめは 4ms か 64 KiB(T26 で決める)。ターミナル 1 枚につきスレッドは 2 本(読み取りとまとめ。設計書 §1.3 #2 は 1 本と書いているので、T27 で設計書を直す)
- **T18 で決めたこと(CSP)**: `csp` と `devCsp` に `style-src-elem 'self' 'unsafe-inline'` と `style-src-attr 'unsafe-inline'` を足した(`style-src 'self'` は残し、`script-src` は変えない)。理由: xterm.js 6.0.0 は実行時に `<style>` 要素を 3 つ作り、truecolor の文字に style 属性を書く。緩める前の設定では、スモークが `style-src-elem` の違反を検出して失敗した(実機で確認)。style 属性の違反はソースで確かめただけ。Tauri が nonce を足すのは `script-src` と `style-src` だけなので、`dangerousDisableAssetCspModification` は不要(Tauri 2.12.5 のソースで確認)。影響: CSS を差し込まれても、`img-src`・`connect-src`・`default-src` が絞られているので外への読み込みはできない。ADR-001 への記録は T27。境界検査に 11 番目の項目(スクリプトは `'self'` と `'none'` だけ)を足した
- **T18 で足したもの**: capabilities に `core:event:allow-listen`・`allow-unlisten`(写しのイベントの購読用。画面からの送信は許さない)。コマンド `report_frontend_error`(CSP 違反・例外・読み込みの失敗を標準エラーに `[arin:frontend-error]` で 1 行。製品の診断機能として常に有効)。スモークの 2 つ目の印 `smoke-terminal`(最初の処理済みの通知で書く)。スモークは画面の失敗の行が 1 行でもあれば失敗にし、アプリが起動したシェルが残らないことも確かめる。`TerminalSurface` に `size()` を足した
- **T18 の未確認**: `npm run dev` は実行していない(起動したまま待ち続けるため)。`devCsp` の `script-src` を緩めていないので、Vite の開発時のスクリプトが止められて動かない可能性がある。計画の「`npm run dev` でプロンプトと `echo ok` を 1 回見る」は未実施で、代わりに実アプリのスモークで入出力を確かめた
- **T19 で分かったこと**: 既定の大きさ(1280×720)で最初の接続は 40 行 × 140 桁。スクロールバックは画面の行数 + 10,000 行。全角は 2 桁ぶんの幅。テストは DOM 描画の要素から表示を読むので、WebGL(T21)では表示のテストをそのまま使えない
- **T23 で決めたこと**: 記録は標準エラーに `[arin:verify] osc52 …`(OSC 52 が始まった回数。本文は持たない)と `[arin:verify] flow …`(5 秒ごと。通知の回数、合計、間隔の最大、未処理の量の最大、止めた回数)。`cfg(debug_assertions)` のときだけ有効。走査器 `OscScanner` は `arin-core` にあり、M4・M6 のアテンションの土台にする(BEL 単独と OSC 9;4 の除外を足す)
