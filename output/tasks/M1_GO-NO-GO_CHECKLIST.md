# M1 の Go/No-Go 確認手順書

- 対象: Arin の M1(ターミナル 1 枚)。ブランチ `feat/m1-terminal`
- 目的: xterm.js と Rust 側の PTY の組み合わせで、Claude Code と Codex が実用に耐えるかを、本人が実機で判定する(PRD §7、設計書 §2.2)
- 判定する人: 本人。AI は合否を判定しない
- 所要時間の目安: 40〜60 分(「ウィンドウが隠れたとき」の 5 分の放置を含む)

結果は、各表の「結果」の欄に `OK` / `NG` / `気になる` と、気づいたことを書き込む。全部を埋めなくてもよい。途中で「これは使えない」と分かった時点で No-Go にしてよい。

## 0. 準備

### 0.1 アプリを作る

リポジトリのルートで実行する。2 つ目は、検証用の記録(`[arin:verify]`)が出るデバッグ版。

```bash
npm run app          # 配布用と同じ .app(速さを見るのはこちら)
npm run app:debug    # デバッグ版の .app(記録を見るのはこちら。動きは遅い)
```

### 0.2 起動のしかた

環境変数で描画方式などを切り替えるので、**Arin の実行ファイルを、いま使っているターミナル(iTerm など)から直接起動する**。Arin の中のシェルに渡す環境変数は Arin が決め直すので、起動元のターミナルの影響は受けない。

```bash
REL=target/aarch64-apple-darwin/release/bundle/macos/Arin.app/Contents/MacOS/arin
DBG=target/aarch64-apple-darwin/debug/bundle/macos/Arin.app/Contents/MacOS/arin

"$REL"                                              # 既定(DOM 描画)
ARIN_RENDERER=webgl "$REL"                          # WebGL 描画
ARIN_RENDERER=webgl ARIN_UNICODE=graphemes "$REL"   # WebGL + 全角幅の別方式
ARIN_VERIFY_GRID=1 "$REL"                           # 9 枚の検証画面(DOM)
ARIN_VERIFY_GRID=1 ARIN_RENDERER=webgl "$REL"       # 9 枚の検証画面(WebGL)
"$DBG" 2> verify.log                                # デバッグ版。記録を verify.log に保存
```

| 環境変数 | 値 | 意味 |
| -------- | -- | ---- |
| `ARIN_RENDERER` | `dom`(既定)/ `webgl` | 描画方式 |
| `ARIN_UNICODE` | `unicode11`(既定)/ `graphemes` | 全角幅と絵文字の幅の決め方 |
| `ARIN_VERIFY_GRID` | `1` | ターミナルを 9 枚、3×3 に並べる検証画面 |

終了は ⌘Q。起動元のターミナルに `[arin:frontend-error]` で始まる行が出たら、画面側で失敗が起きている(CSP 違反、例外、WebGL から DOM への切り替わりなど)。その行を控えておく。

### 0.3 いまの描画方式の確かめ方

ウィンドウの上部(版の表示の隣)に、実際に使っている描画方式が小さく `dom` か `webgl` と出る。**WebGL を指定したのに `dom` と出ていたら、WebGL を作れずに DOM に切り替わっている。** その場合は起動元のターミナルの `[arin:frontend-error]` の行を控える。

### 0.4 現時点で分かっていること(自動テストと計測の結果)

| 項目 | 結果 |
| ---- | ---- |
| 実アプリで、ログインシェルの出力が画面に届き、処理済みの量が戻る | スモークで確認済み(DOM・WebGL・9 枚のそれぞれ) |
| 実アプリで WebGL のコンテキストを 9 個作れる | スモークで、DOM への切り替わりの報告が出ないことを確認済み |
| スクロールバック 10,000 行、全角が 2 桁ぶんの幅、色、寸法の追従 | Playwright の WebKit で確認済み(実機の WKWebView とは別のビルド) |
| 10 万行(7.7 MB)の `cat`、PTY から送り先まで(Rust 側だけ) | 約 41ms(`testreport/perf/latest.md`) |
| 起動からターミナルの表示準備まで | 約 312ms |
| メモリ(アプリ本体 + WebKit、ターミナル 1 枚) | 79.7 MiB |
| **画面の見た目、日本語入力、実際の ⌘ キー、体感の速さ** | **誰も見ていない。この手順書で確かめる** |

計測をやり直すときは `npm run perf`(約 30 秒。結果は `testreport/perf/latest.md`)。

### 0.5 分かっている制約(M1 の時点)

| 制約 | 影響 | 扱い |
| ---- | ---- | ---- |
| ターミナルの cwd はホームフォルダ固定 | プロジェクトのフォルダで始まらない | M2 でプロジェクトのルートになる |
| タブ、複数プロジェクト、ファイルツリーは無い | ターミナルは 1 枚だけ(検証画面のときだけ 9 枚) | M2 以降 |
| メニューバーは「Arin」と「編集」だけ | ⌘M、⌘W などは効かない | M2 以降で足す |
| マウスを使う TUI の動作中は、ドラッグでの文字選択が TUI に取られる | そのままでは選択できない | **Option を押しながらドラッグ**すると選択できる |
| 古い形式(X10)のマウス報告で、座標が大きいものは PTY に届かない | 古い TUI で、画面の右や下の方のクリックが効かないことがある。いまの主な TUI が使う形式(SGR)は影響を受けない | 困る TUI があれば 4 章に書く(T27 で直す) |
| 流量制御のしきい値は、作り直さないと変えられない | この場では値を変えて比べられない | いまの値での様子だけを見る。変えたい場合は 4 章に書く |
| Option キーは Meta として働かない | Option+← などが、いつものターミナルと違うことがある | 2.7-3 で確かめ、4 章で決める |
| 隠したまま新しく作るターミナルの寸法 | M1 の画面では起きないので未確認 | M2(タブ)と M4(タイル)で扱う |

### 2.9 流量制御

**デバッグ版**で見る。アクティビティモニタを開き、「arin」と、WebKit のプロセス(名前に「Web Content」を含むもの。Arin の起動で増えたもの)のメモリを見ておく。

### 2.10 CSP

AI が確かめた結果を読んで、了承するかを決める(実機での操作は要らない)。

| 項目 | 内容 |
| ---- | ---- |
| 緩めた内容 | `style-src-elem 'self' 'unsafe-inline'` と `style-src-attr 'unsafe-inline'` を足した。`style-src 'self'` は残し、`script-src` は緩めていない |
| 理由 | xterm.js 6.0.0 は実行時に `<style>` 要素を作り、色付きの文字に style 属性を書く。緩める前の設定では、実アプリで `style-src-elem` の違反が出てターミナルが正しく描けなかった(スモークで確認) |
| 影響 | スタイルの差し込みを CSP では止められなくなる。ただし `img-src`・`connect-src`・`default-src` は絞ったままなので、CSS から外部への読み込みはできない。スクリプトの実行は従来どおり止める |
