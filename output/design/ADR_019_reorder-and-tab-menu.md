# ADR-019: プロジェクトとタブをドラッグで並べ替え、タブの右クリックでまとめて閉じる

- 状態: Accepted(本人が要望と選択肢を決めた。実機の手触りは本人の確認待ち)
- 日付: 2026-11-24
- 関係: ADR-007 の (b)(pointer のイベントで作るドラッグ)、ADR-015 の 3・4(エディタのタブと閉じる確認)

## 背景(本人の要望。原文)

「プロジェクトの順番をD&Dで入れ替えられるといいな。あと、タイルではないときのタブの入れ替えもD&Dでできるといいな。あと、タイルではないときのタブの右クリックで、よくある、これより右を閉じるがあるといいな。」

本人が選んだこと:

- タブの並べ替えは「同じ種類の中だけ」(ターミナルはターミナルの中、エディタはエディタの中。ターミナルが左、エディタが右のまま)
- メニューの項目は「タブを閉じる」「ほかのタブを閉じる」と「これより右を閉じる」
- 閉じるタブに動作中のターミナルか未保存のエディタがあれば「あれば確認を出す」(無ければ確認なしで閉じる)

## 決定

### 1. 並びは Rust が持ち、写しで届く

| 並び | 持ち主 | コマンド | 保存 |
| ---- | ------ | -------- | ---- |
| プロジェクト | `ProjectStore`(`move_to`) | `move_project { projectId, toIndex }` | する(`state.json` の `projects` の並びそのもの。形は変えない) |
| ターミナルのタブ | `TerminalStore`(`move_to`。同じプロジェクトの中) | `move_terminal_tab { terminalId, toIndex }` | しない(タブは保存しない) |
| エディタのタブ | `EditorStore`(`move_to`。同じプロジェクトのエディタの中) | `move_editor_tab { editorId, toIndex }` | しない |

- `toIndex` は「動かしたあとの位置」(0 から。末尾より大きければ末尾)。同じ位置なら何もせず写しも送らない
- 選択・表示中のタブ・タブの番号と名前は変えない。タイルの並びはプロジェクトの順・タブの順のままなので、並べ替えるとタイルも付いていく(ページはフォーカス中のタイルのページに合わせ直す)
- 種類をまたぐ並べ替えの口は作らない(「同じ種類の中だけ」)。画面もドラッグの組を種類で分ける

### 2. タブをまとめて閉じるのは 1 つのコマンド

`close_tabs { projectId, terminalIds, editorIds, confirmed }` → `CloseTabsOutcome`(`needsConfirmation { running, unsaved }` か `closed`)。

- 閉じるタブのうち動作中のターミナル(前面がシェル以外。削除・終了の確認と同じ判定)か未保存のエディタがあり、`confirmed` が偽なら、何も変えずに一覧を返す。画面は確認を出し、「閉じる」で `confirmed: true` で呼び直す(`remove_project` と同じ形)
- 閉じたらターミナルのセッションをまとめて終わらせる(削除と同じく同時に終わらせる)。エディタの未保存の変更は捨てる
- ほかのプロジェクトのタブ・もう無い ID は無視する
- 表示中のタブを閉じたときの次の表示は 1 枚ずつ閉じたときと同じ。閉じたあとに何も出ていなくてエディタが残っていれば、残った最初のエディタを出す(「ほかのタブを閉じる」でエディタを残したときに空にしない)
- 画面から N 回 `close_terminal`・`close_editor` を呼ぶ形にしなかった: 確認を 1 回にまとめられず、途中の写しで表示中のタブが何度も替わる

### 3. メニューと「右」

右クリック(または Shift+F10)で「タブを閉じる」「ほかのタブを閉じる」「これより右を閉じる」。「右」はタブバーに見えている並び(ターミナル → エディタ)での右なので、ターミナルのタブで選ぶとエディタも閉じる。
ほかのタブが無い・右にタブが無いときは項目を薄くして選べなくする(消さない)。組み立ては `src/logic/menu/tabMenu.ts`。タブ表示だけ(タイルにはタブバーが無い)。

メニューの「タブを閉じる」も確認の規則は同じ(動作中・未保存があれば確認)。⌘W と × ボタンは今までどおり(ターミナルは確認しない。エディタは未保存なら「保存」「保存しない」「キャンセル」の確認)。【仮定】メニューは 3 つとも同じ確認にそろえた。

### 4. ドラッグは pointer のイベントで作る(ADR-007 の (b) と同じ)

`src/ui/shell/useReorderDrag.ts`。HTML 標準のドラッグ&ドロップは使わない(WKWebView ではファイルのドロップと取り合う。ツリーと同じ理由)。

- しきい値 4px を超えるまではクリック。閉じるボタンからは始めない。⌃ 付きのクリック(右クリック)では始めない
- 掴んだ項目は不透明の札にして浮かせ、並びの向きにだけポインタに付いて動く。あいだの項目が掴んだ項目の大きさぶん滑って隙間を空ける(macOS のタブ・一覧と同じ)。線の印は引かない(隙間が落とす位置)。動きを減らす設定では滑らせない
- 落とす位置は、ドラッグを始めたときの各項目の中心で決める(滑った位置で決めると行ったり来たりする)。規則は `src/logic/dnd/reorder.ts`
- Esc・ウィンドウのフォーカスを失う・ポインタの捕捉を失うと取り消す。ドラッグのあとに届く click は捨てる(カードやタブを選ばない)

## 却下した案

- **線の印(Finder のサイドバーの線)**: 掴んだ項目がポインタに付いて動くと線と重なり、取り消し線のように見えた(撮った画像で確かめた)
- **キーボードでの並べ替え**: 求められていない。左右の矢印・Home・End・Delete の今の動きはそのまま

## 残っている確認(本人)

- 実機のマウスとトラックパッドでの手触り(Playwright の WebKit は WKWebView と別のビルド)
- 離してから写しが届くまでの一瞬、元の並びに戻って見えないか
