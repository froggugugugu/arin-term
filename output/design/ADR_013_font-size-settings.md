## コンテキスト

本人の要件の追加(2026-11-16)。本人が決めたこと:

1. 値は `state.json` に保存する(設定画面の値はアプリが管理する状態)。`settings.toml` は今までどおり人だけが書き、アプリは書き換えない。フォントサイズは設定画面だけで扱い、`settings.toml` には項目を作らない
2. ⌘, は設定画面を開く。いま ⌘, に割り当てている「設定ファイルを開く…」(M4.5。`app.open-settings`)は、設定画面の中のボタンとメニューの項目に移す
3. ⌘+・⌘− での拡大縮小は今回は入れない(あとから足せる形にしておく)。フォントの種類・配色も今回は入れない

フォントの大きさは元は M6 の T56(FR-049。`settings.toml` の `[terminal]` の `font_size`。設計書 §6.2 の表は既定 13)にあった。本 ADR で M4.6 に前倒しし、置き場所を `state.json` に替える。

実装から確かめたこと(2026-11-16 の `feat/m4.6-font-settings`):

- **ターミナルの文字の大きさはいま指定していない**。`src/terminal/xterm/XtermEngine.ts:57-63` の `new Terminal({...})` は `fontSize` を渡さないので、xterm.js 6.0.0 の既定の **15**(`node_modules/@xterm/xterm/src/common/services/OptionsService.ts:25`)で描いている。設計書 §6.2 の「`terminal.font_size` 既定 13」は実装と違う。フォントの種類・行の高さも xterm.js の既定のまま
- 寸法合わせは `XtermSurface.fit()`(`FitAddon.fit()`。隠しているときと置き場所が DOM に無いときは何もしない。`XtermEngine.ts:107-110`)。`TerminalHost` が置き場所の `ResizeObserver` で 50ms 止んだら `TerminalManager.fit` を呼ぶ(`src/ui/terminals/TerminalHost.tsx:29-36`)。行・桁が変わると xterm.js の `onResize` → `TerminalManager` の直列の送信 → `resize_terminal`(`TerminalManager.ts:418-442`)。**文字の大きさだけを変えても置き場所の大きさは変わらないので、`ResizeObserver` は鳴らない**。隠したターミナルは `display: none` のまま取り込みを続け、表示に戻すと `fit` し直す(`TerminalManager.ts:162-171`)
- **画面の文字の大きさの基準は `--font-size-l: 13px`**(`src/ui/design/tokens.css:113-116`。s 11・m 12・l 13・xl 15)。部品の CSS は文字の大きさをすべてこの 4 つのトークンで書いている(`font-size` の直書きは 0)。行の高さもトークン(`--header-height` 30・`--tab-bar-height` 28・`--tile-title-height` 24・`--sidebar-item-height` 28・`--sidebar-section-height` 26・`--button-height` 22・`--tree-row-height` 22・`--tree-toolbar-height` 26・`--menu-item-height` 22)。部品の CSS に残る px の直書きは、線・輪・アイコン・余白・幅の上下限が大半で、文字の入れ物の直書きはツリーの名前の入力欄の `height: 18px`・`line-height: 18px`(`src/ui/tree/TreeView.css:178`・`188`)だけ
- **ツリーの仮想スクロールの行の高さは、部品が付いたときに 1 回だけ CSS から読む**(`src/ui/tree/FileTreeView.tsx:68-72`・`183`・`214-217`。`getComputedStyle(...).getPropertyValue("--tree-row-height")` を `parseFloat`)。変数をあとから替えても読み直さない。また変数を `calc()` で書くと、`getPropertyValue` は計算前の文字列を返すので `parseFloat` が失敗し、既定の 22 に落ちる
- 表示モード(`ui.displayMode`)の前例: 規則は `arin-core`(`layout/tiles.rs`・`workspace/display.rs`)、保存は `persistence/codec.rs`(`UiSection`。知らない値は退避せず既定。既定のあいだは書かない)、口は `Workspace::set_display_mode` → `SessionRegistry::set_display_mode`(変わったら `notify`)→ コマンド `set_display_mode`(`src-tauri/src/commands/layout.rs:33-38`)。`notify` が写しを直列に送り、保存を予約する(`sessions.rs:882-896`)。範囲を持つ数の前例はペインの寸法(`layout/panes.rs` の `PaneSizes::sanitized`。数でない・負は初期値、最小未満は最小)
- ショートカットの表(`crates/arin-core/src/shortcuts/table.rs`)は 23 行。`app.open-settings` = `Cmd+,`(受け口 `menu-item`)。**すべての行がキーを持つ**(`ShortcutBinding::accelerator` は `KeyChord` で `Option` でない。`from_bindings` が足りない行を拒む)。メニューの自前の項目は表の行からしか作っていない(`src-tauri/src/menu.rs:257-285`)。「設定ファイルを開く…」は `on_menu_event` の `C::AppOpenSettings` → `settings::open_from_menu`(`menu.rs:304`、`src-tauri/src/settings.rs:334-349`)
- 画面への「メニューから画面へ」の前例は `menu-command` イベント(`MenuCommand`。いまは `"select-all"` だけ。`crates/arin-core/src/workspace/events.rs:16-18`)。`main.tsx:72` が `TerminalManager.handleMenuCommand` へつなぐ
- 画面内のダイアログの前例は `ConfirmDialog`(`src/ui/dialogs/ConfirmDialog.tsx`。モーダルの `<dialog>`、開くとボタンにフォーカス、Tab を自前で回す、Esc で取り消し、閉じたら前のフォーカスへ戻す)。開閉の状態は `uiStore` が持つ(`src/state/uiStore.ts`。Rust に送らない)
- ⌘W(`terminal.close-tab`)は確認なしで表示中のタブを閉じ、シェルを終わらせる(`sessions.rs:528-531`)。キーが WKWebView の keydown で取り消されたときにメニューへ回るかは、リポジトリの中で記述が食い違う(`menu.rs:8` と ADR-012 の 3 #7 は「OS が WKWebView より先に受ける」、`XtermEngine.ts:67-69` は「取り消されていなければメニューの項目へ回す」)。実機では確かめていない

## 判断

**文字の大きさは「ターミナル」と「画面」の 2 つの整数(CSS ピクセル)として `state.json` の `ui` に保存し、Rust の `Workspace` を正本として写しで画面へ流し、⌘, で開く画面内のシート型の設定画面で、1 刻みのステッパーで即時に変える。**

### 1. 保存の形(`state.json` の `ui`)

| キー | 型 | 既定 | 範囲・刻み【仮定。【要確認】1】 | 備考 |
| ---- | -- | ---- | ------------------------------- | ---- |
| `ui.terminalFontSize` | 整数(CSS ピクセル) | **15**(いまの xterm.js の既定と同じ) | 9〜28、1 刻み | 全ターミナルに共通(プロジェクトごと・タブごとには持たない) |
| `ui.interfaceFontSize` | 整数(CSS ピクセル) | **13**(いまの `--font-size-l`) | 11〜18、1 刻み | 画面の文字の基準。ほかの大きさはここから決める(4) |

- **既定の値のあいだは書かない**(`ui.displayMode` と同じ。触っていない人の `state.json` は M4.5 までと同じ形のまま。将来の版で既定を変えたとき、触っていない人は新しい既定に付いていく)
- **読むときの扱い**(`ui.displayMode` と `PaneSizes` の前例を合わせた形。どれも退避しない・知らせない):
  - 無い・`null`・数でない(文字列・真偽・配列など)・無限大・NaN → 既定
  - 整数でない数 → 四捨五入(.5 は大きいほう)してから下の範囲の扱い
  - 範囲の外 → 近いほうの端に留める(古い版・新しい版を行き来しても、利用者の選んだ大きさに近い値で始まる。§7.2 の「範囲外は既定値に戻す」は人が書く設定ファイルの規則で、アプリが書く状態ファイルには当てない)
  - 1 つの値のためにプロジェクトの一覧を退避しない(`lenient_display_mode` と同じ考え)
- **版は 1 のまま**(キーの追加。`STATE_SCHEMA_VERSION` を上げない。設計書 §6.2「版の移行」)。古い版のアプリは知らないキーとして無視して読める(保存し直すとキーは消え、既定に戻る。M4.6 より前の版に戻した場合だけの話で、許す)
- 規則(範囲・既定・刻み・読むときの整え方)は `arin-core` の新しいファイル `crates/arin-core/src/layout/font_sizes.rs` に置く(`PaneSizes` と並ぶ「保存する画面の寸法」。入出力なし)。型 `FontSizes { terminal: u16, interface: u16 }` と `FontSizeTarget`(`"terminal"` / `"interface"`)

### 2. 状態の持ち主と流れ(表示モードの前例にならう)

```text
設定画面のステッパー
  → コマンド step_font_size({ target, delta }) / reset_font_sizes()
  → SessionRegistry → Workspace(規則は layout::font_sizes)
  → 変わったら notify(写しを直列に送る。保存を予約)
  → app-snapshot の fontSizes → 画面(ターミナルへ 3、画面の CSS へ 4)
  → 0.5 秒まとめて state.json の ui.terminalFontSize / ui.interfaceFontSize
```

- 正本は Rust の `Workspace`(`layout` と同じく `Workspace` が直接持つ。ストアは増やさない)。画面は写しを映すだけで、値を自分で持たない(`AppSnapshot` は丸ごと置き換える決まり)
- **コマンドは「いくつ動かすか」で渡す**: `step_font_size(target: FontSizeTarget, delta: i32)`(範囲で留める。変わったときだけ写しを送る)と `reset_font_sizes()`(両方を既定に戻す)。理由: 画面が「今の値 + 1」を計算して送ると、写しが届く前に続けて押したとき同じ値を 2 回送って 1 つしか上がらない。`delta` なら Rust がロックの中で順に足すので、押した回数どおりになる。また ⌘+・⌘−(本人の決定 3。今回は入れない)を足すときは、メニューの項目から `SessionRegistry::step_font_size(Terminal, ±1)` を呼ぶだけで済む(`view.*` の 4 行と同じ形)
- 値を直接指定する `set_font_size` は作らない(今回の画面は刻みとリセットだけ。要れば足す)
- **写しの形**: `AppSnapshot` に `fontSizes: FontSizesSnapshot` を足す(項目の追加なので `SNAPSHOT_SCHEMA_VERSION` は 1 のまま)。中身は `terminal` と `interface` のそれぞれに `{ value, min, max, defaultValue }`。範囲と既定を写しに載せて、画面に規則の数を写さない(写しのたびに数バイト増えるだけ。生成した定数の見本を画面に置いて一致を検査する方式=`defaultShortcuts.ts` より軽い)
- 保存は既存の `persistence.rs` の保存のスレッドのまま(写しを送ると保存が予約される)。`settings.toml` には触れない

### 3. ターミナルへの当て方

- `TerminalSurface`(`src/terminal/engine.ts`)に `setFontSize(px: number): void` を足す。`TerminalEngine.createSurface` に初めの大きさを渡せる形にする(作ってから変えると、最初の寸法の計算をやり直すため)
- `TerminalManager` が今の大きさを 1 つ持ち(`setFontSize`)、持っている**すべてのサーフェス**に当てる。新しく作るサーフェスはその大きさで作る。写しから当てるのは `src/state/terminalSync.ts`(写しの購読の中で、`present` より前に当てる=隠したまま作るサーフェスも新しい大きさで作る)
- **表示中のターミナル**(タブ表示の 1 枚、タイル表示の最大 9 枚、拡大中の 1 枚): 大きさを当てたあと `fit` を呼び直す(置き場所の大きさは変わらず `ResizeObserver` が鳴らないので、明示して呼ぶ)。行・桁が変われば今の経路(`onResize` → 直列の送信 → `resize_terminal` → PTY の寸法 → シェルに SIGWINCH)で通知する。シェルは終わらせない・つなぎ直さない。最後に表示した寸法(`#lastShownSize`)も更新する
- **隠しているターミナル**(ほかのタブ・ほかのプロジェクト・ほかのページのタイル): `XtermSurface` は大きさを覚えるだけにして、**表示に戻すとき**(`setVisible(true)`)に当ててから `fit` する【仮定】。理由: `display: none` の要素の中では xterm.js が文字の寸法を測れず(幅・高さが 0)、測り損ねた寸法で行・桁を決めるおそれがある。隠しているあいだの PTY の寸法は古いまま(今も、隠しているあいだにウィンドウの大きさを変えたときと同じ)。表示に戻した時点で行・桁が決まり直り、寸法が送られる
- 続けて押したときの重さ: 1 回の変更でスクロールバック(最大 10,000 行)の折り返し直しが表示中の枚数ぶん起きる。`TerminalManager` は大きさの変更を 1 フレームにまとめ、最後の値だけを当てる(`src/logic/coalesce.ts` の `createCoalescer` を使う)【仮定】。タイル 9 枚での体感は本人が確かめる(T73a)
- 文字の大きさ以外(フォントの種類・行の高さ・配色)は今回変えない(本人の決定 3)

### 4. 画面への当て方(1 つの基準値から決める)

- **基準値は `interfaceFontSize`(既定 13 = いまの `--font-size-l`)**。追従させるトークンの値は、純粋な関数 `interfaceMetrics(size)`(新しいファイル `src/logic/appearance/interfaceMetrics.ts`)が**整数の px** で返す: `round(既定の値 × size / 13)`。既定の 13 では、いまの `tokens.css` の値と 1 つ残らず同じになる(テストで確かめる。見た目は変わらない)
- 当てるのは 1 か所(`src/ui/design/applyInterfaceMetrics.ts`)。写しの `fontSizes.interface.value` が変わったら、`document.documentElement.style.setProperty` で `:root` の変数を上書きする。`tokens.css` の値は既定のまま残す(写しが届く前と、当てるのに失敗したときの値)。CSS の `calc()` で比例させる方式は採らない(ツリーが変数を読むとき計算前の文字列になり、行の高さが既定の 22 に落ちる。上の「確かめたこと」)
- **追従させるもの**(文字と、文字を入れる行の高さ。【要確認】5):
  - 文字の大きさ: `--font-size-s`(11)・`--font-size-m`(12)・`--font-size-l`(13)・`--font-size-xl`(15)
  - 行の高さ: `--header-height`(30)・`--tab-bar-height`(28)・`--tile-title-height`(24)・`--sidebar-item-height`(28)・`--sidebar-section-height`(26)・`--button-height`(22)・`--tree-row-height`(22)・`--tree-toolbar-height`(26)・`--menu-item-height`(22)
  - 新しいトークン `--tree-input-height`(既定 18。ツリーの名前の入力欄の `height`・`line-height` の直書き 2 か所を置き換える)
- **追従させないもの**: 余白(`--space-*`)、角丸(`--radius-*`)、線と輪(1px・2px の区切り線・フォーカスの輪)、境界の掴みしろ(`--divider-hit`)、アイコンとアイコンのボタン(`--icon-button-*`・ツリーのアイコン 12〜16px・タブの閉じるボタン 18px)、印(`--project-dot-size*`・`--attention-dot-size*`)、区分けのボタン(`--segmented-*`。中身はアイコン)、幅の上下限(タブの 96〜200px、メニューの 200〜320px、確認ダイアログの 420px、ドラッグの札の 240px。はみ出す文字は今までどおり省略する)、ペインの最小寸法(`PaneSizes`・`paneLayout.ts`)、すりガラスのぼかし。理由: macOS の「サイドバーのアイコンの大きさ」と同じく、文字の読みやすさに効くのは文字と行の高さで、余白と線まで比例させると密度だけが変わり、細い線がにじむ(整数に丸めない値になる)
- **ツリーの仮想スクロール**: `FileTreeView` は行の高さを CSS から 1 回読むのをやめ、写しの基準値から `interfaceMetrics(size).treeRowHeight` で受け取る(CSS の変数と同じ関数・同じ値。ずれない)。行の高さが変わったら窓を計算し直し、選択中の行が見える位置を保つ
- **ターミナルの中の文字は画面の大きさに追従しない**(ターミナルは 3 の値だけで決まる)。ただし画面の大きさを変えるとタブバー・タイルのタイトルバーの高さが変わり、ターミナルの置き場所が縮む・伸びるので、`ResizeObserver` で行の数が変わり PTY に寸法が送られる(シェルは続く)
- 写しが届く前の 1 フレームは既定(13)で描かれうる(ウィンドウは起動時から見えている。`tauri.conf.json` に `visible` の指定が無い)。プロジェクトの一覧も写しが届くまで空なので、目立たない見込み【仮定】

### 5. 設定画面の形

- **ウィンドウ内の部品**にする(新しい `src/ui/settings/SettingsDialog.tsx`)。別ウィンドウにしない。理由: 確認ダイアログを画面内で作る決まり(設計書 §9.1・§1.3 #14。自動テストできる)と同じ。別ウィンドウは Tauri の窓を増やし、窓ごとの CSP・イベント・E2E の足場が要る
- **形はシート**(macOS の設定のシートにならう): モーダルの `<dialog>`(`role="dialog"`。確認ではないので `alertdialog` にしない)。上部の帯の下に、横の中央に付けて出す。幅 440px【仮定】。地は `--color-surface`、影は既存の `--shadow-popup`、角は `--radius-m`。**背景を暗くしない**(`::backdrop` は透明。変えた大きさを後ろのターミナルとツリーで見ながら選べるようにする。外の操作はモーダルなので効かない)【要確認】4
- **中身**(上から):
  1. 見出し「設定」(`--font-size-l`、`--font-weight-strong`、中央)
  2. 「文字の大きさ」の組: 行は「ターミナル」と「画面」の 2 行。左に名前、右に値(例「15 pt」。数字は等幅の数字 `tabular-nums`)とステッパー。「画面」の行の下に小さく薄い説明「サイドバー・タブ・ツリー・メニューの文字」。行の間は細い区切り線(`--color-separator`)
  3. 「ショートカット」の組: 説明「キーは設定ファイル(settings.toml)で変えます」と、ボタン「設定ファイルを開く…」
  4. 下端: 左に「既定に戻す」(両方が既定のときは無効)、右に「完了」(既定のボタン。`button--primary`)
- **値の変え方はステッパー**(macOS の `NSStepper` にならい、値の右に ▲▼ を縦に重ねた小さな部品)。スライダーにしない。理由: 1 刻みの整数で範囲が 8〜20 段と狭く、いまの値を数で正確に読めるほうが選びやすい。スライダーは細かい値を狙いにくく、つまみを動かしているあいだに写しとコマンドが何十回も往復する
- **即時に反映**(押すたびに `step_font_size`。macOS の設定と同じく「適用」「取り消し」は無い)。範囲の端では ▲ か ▼ を無効にする(範囲は写しの `min`・`max`)
- **開閉の状態の持ち主は `uiStore`**(`settingsOpen: boolean`、`openSettings()`・`closeSettings()`。Rust に送らない。確認ダイアログと同じ)。開いていれば ⌘, を押し直しても 1 つのまま(開き直さない)
- **閉じ方**: 「完了」、Esc、Return(ボタン以外にフォーカスがあるとき)、⌘W【要確認】3。閉じたら開く前にフォーカスがあった要素(ふつうはターミナル)へ戻す
- **キーボード操作**: 開くと「ターミナル」のステッパーにフォーカス。Tab・Shift+Tab は、ターミナルのステッパー → 画面のステッパー → 設定ファイルを開く… → 既定に戻す → 完了 を回る(`ConfirmDialog` と同じく自前で回す。macOS の既定では Tab がボタンに止まらないため)。ステッパーは `role="spinbutton"`(`tabindex="0"`)で、↑ で 1 大きく・↓ で 1 小さく、Home で最小・End で最大。▲▼ のボタンはマウス用で Tab に止めない(`tabindex="-1"`)
- **読み上げの名前**: ダイアログは「設定」。ステッパーは「ターミナルの文字の大きさ」「画面の文字の大きさ」、`aria-valuenow`・`aria-valuemin`・`aria-valuemax`、`aria-valuetext` は「15 ポイント」。▲▼ のボタンは「大きくする」「小さくする」
- 表示の単位は「pt」【仮定】(WKWebView の CSS ピクセルは macOS のポイントと同じ大きさ。ターミナルのアプリの多くが pt で出す)
- 「既定に戻す」は確認を挟まない(戻せる操作なので)
- ほかの確認ダイアログ(終了・削除・衝突・移動)が開いているあいだに ⌘, が来たら、設定画面を開かない【仮定】(モーダルを 2 枚重ねない)。設定画面を開いているあいだに終了の確認が届いたら、終了の確認を上に重ねる(終了の確認は止められない要求のため。閉じると設定画面に戻る)
- **デザインの方針(本人の指示)**: 「AI にありがちなデザインを避け、Apple のデザインらしく、ハイセンスに」。macOS の設定のシートのように控えめにする: 色は既存のトークンだけ(新しい色を足さない)、グラデーション・絵文字・大きな角丸のカード・影の重ね・アイコンの飾り・色付きの見出しを使わない。文字はシステムフォント、強調は太さだけ。組は箱で囲まず、区切り線と余白で分ける。ライトとダーク、すりガラスの上で、Playwright の画像を撮って目で確かめてから終える(T70b)

### 6. ⌘, の割り当ての替え方(ショートカットの表)

**採る案(A)**: 表の行 `app.open-settings` の ID とキー(`Cmd+,`)と受け口(`menu-item`)はそのままにし、**意味を「設定画面を開く」に替える**。メニューの文言は macOS の標準の「設定…」にする。「設定ファイルを開く…」は**表の外の、キーの無いメニューの項目**にする(項目の ID は `app.open-settings-file`。`menu.rs` の定数で、`ShortcutCommandId` には足さない)。

- 表は 23 行のまま。「すべての行が既定のキーを持つ」決まり(`from_bindings`)はそのまま守られる。生成物(`ShortcutCommandId.ts`・`defaultShortcuts.json`・`defaultShortcuts.ts`)の中身は変わらない(`table.rs` の説明の文だけ替える)
- アプリ名のメニューの並び: 「設定…」(⌘,)・「設定ファイルを開く…」(キーなし)・区切り線・隠す・ほかを隠す・すべてを表示・区切り線・終了
- 「設定…」が選ばれたら(キーでもメニューでも)、Rust は画面へ `menu-command` の新しい値 `"open-settings"` を送る(`MenuCommand::OpenSettings`)。画面は `uiStore.openSettings()` を呼ぶ(`src/logic/keys/menuCommand.ts` の振り分けに足す)。Rust は設定画面が開いているかを知らない
- 「設定ファイルを開く…」(メニューの項目と、設定画面のボタン)は、今の `settings::open_from_menu` と同じ処理(無いときだけ見本を作って既定のアプリで開く。ADR-012 の 6)。画面のボタンは新しいコマンド `open_settings_file`(引数なし。パスは画面を通らない)を呼ぶ
- **M4.5 で `settings.toml` に `"app.open-settings" = "…"` を書いている場合**: 書いたキーで設定画面が開く(ID が同じで、意味が「設定」のまま近い)。設定ファイルを開くのはメニューか設定画面のボタンになる。知らせは出さない(問題のある行ではないため)。M4.5 は本人の完了確認の前なので、書いている人は本人だけの見込み
- **見本の文**(`sample_settings_toml`): 行の並び(`# "app.open-settings" = "Cmd+,"`)は変わらない。先頭の説明に 1 行足す: 「文字の大きさはこのファイルではなく、アプリの「設定…」(⌘,)で変えます」(`[terminal]` に `font_size` を書いても効かないことが分かるように)。見本は無いときだけ作るので、既にある設定ファイルは変わらない
- `settings.toml` に `[terminal]` の `font_size` を書いた場合: M4.5 のまま、知らない節として黙って無視する(知らせない)

### 7. ⌘+・⌘− をあとから足す形

- 規則(`FontSizes` の刻みと範囲)とコマンド(`step_font_size`)は `delta` を受けるので、メニューの「表示」に「文字を大きく」「文字を小さく」「実際の大きさ」を足すときは、表に 3 行(受け口 `menu-item`)と `on_menu_event` の 3 行を足すだけで済む
- 足すときの注意(今回は入れない): `KeyChord` は `+` のキーを書けない(区切りと同じ文字。ADR-012 の 1)ので、⌘+ は `Cmd+=`(US の配列の ⌘= と同じキー)と書く。JIS の配列では `=` が ⇧- の位置にあり打ち方が変わる(`docs/development-patterns.md` §6 の「JIS 配列で打てない記号のキーを既定にしない」)。足すときに JIS で打てるかを確かめる

## 検討した代替案

- 値を `settings.toml` の `[terminal]` の `font_size` に置く(T56 の元の案): 設定画面からアプリが設定ファイルを書き換えることになり、ADR-005・ADR-012 の「人だけが書く。アプリは書き換えない(コメントと並びを壊さない)」に反する。本人の決定 1 とも違う。採らない
- 値を画面だけ(`localStorage` など)に置く: 正本が Rust と画面に分かれ、`state.json` の退避・差し替え(`ARIN_STATE_DIR`)・保存の時機の仕組みが効かない。テストの状態フォルダの閉じ込めも崩れる。採らない
- 画面の大きさを CSS の `zoom` や `transform: scale` で一括に変える: 線・アイコンまでにじみ、ターミナルの置き場所も拡大されて xterm.js の寸法の計算(画面のピクセルと CSS ピクセルの比)が狂う。WebKit の `zoom` はマウスの座標とドラッグの計算(`useTreeDrag.ts`)にも響く。採らない
- 画面の大きさを `calc(var(--ui-font-size) * …)` の CSS だけで比例させる: 値が整数にならず細い線と行がにじむうえ、ツリーが行の高さを読めなくなる(4)。採らない
- 別ウィンドウの設定画面(macOS のアプリの多くの形): 5 のとおり、窓を増やす足場が重く、確認ダイアログを画面内で作る決まりとも違う。採らない
- スライダー: 5 のとおり。採らない
- 値を写しに載せず、`get_font_sizes` のコマンドと専用のイベントで送る: `ui.displayMode` の前例(写しで送る・`notify` が直列に送る)から外れ、古い値があとから届く問題(`docs/development-patterns.md` §6)をもう一度解くことになる。採らない

## 影響

### ポジティブ

- 文字の大きさの正本が 1 つ(Rust の `Workspace`)で、保存・差し替え・テストの閉じ込めは `state.json` の仕組みをそのまま使える
- 画面の文字と行の高さが 1 つの基準値と 1 つの関数から決まり、ツリーの仮想スクロールと CSS がずれない。既定の 13 では見た目が変わらない
- ⌘+・⌘− は表に行を足すだけで入れられる(7)
- 表の決まり(全行がキーを持つ)と生成物を変えずに ⌘, を設定画面へ移せる(6)

### ネガティブ

- PRD の N5(他人向けの設定 UI の作り込み)と FR-057 の「GUI 設定画面は最小限」に近づく。設定画面は本人の要件の追加によるもので、項目は文字の大きさ 2 つと「設定ファイルを開く…」だけに留める。PRD への反映(FR の追加、FR-049 の分割、N5 との線引き)は本人の判断が要る
- 設計書 §6.2 の「`terminal.font_size` 既定 13」は実装(15)とも本 ADR(`state.json`)とも違う。T72 で直す
- `app.open-settings` の意味が M4.5 と変わる(「設定ファイルを開く」→「設定画面を開く」)。M4.5 の `settings.toml` にこの行を書いた人のキーは、設定画面を開くキーになる(6)
- ターミナルの大きさを変えるたびに、表示中の枚数ぶんスクロールバックの折り返し直しが起きる(タイル 9 枚で重くなりうる。3 で 1 フレームにまとめる)
- 隠しているターミナルの PTY の寸法は、表示に戻すまで古いまま(3)
- 写しが届く前の 1 フレームは既定の大きさで描かれうる(4)
