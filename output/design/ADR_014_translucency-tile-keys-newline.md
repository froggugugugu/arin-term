# ADR-014: 透過の設定、タイルの番号キー、Shift+Enter の改行(M4.7)

- 状態: Proposed(本人が 2026-11-17 に実機を触って出した要望。決定の中身は AI が決めた。本人の確認待ち)
- 日付: 2026-11-17
- 関係: ADR-010(すりガラス)、ADR-011(タイル表示)、ADR-012(ショートカットの表)、ADR-013(設定画面)

## 背景(本人の要望。原文)

1. 「透過設定が設定画面に無いので追加してください。」
2. 「ターミナルの背景の設定が効いていません」→ 確認の回答は「ターミナルも透けてほしい」
3. 「タイル表示時、フォーカスの切り替えをは Cmd+1〜9 で切り替えられると嬉しい。半透明で各ターミナルの右上に「#1」「#2」...と表示されると直感的だ。」
4. 「ターミナル内で、改行をしたいがわからない。」

ADR-010 はターミナルの置き場所を不透明の黒に固定していた。これを改める。

## 決定

### 1. 透過の値(規則は `arin-core`、保存は `state.json`)

ADR-013 の文字の大きさと同じ作りにする。

| 対象 | `state.json` のキー(`ui` の下) | 既定 | 範囲 | 刻み | 意味 |
| ---- | ------------------------------ | ---- | ---- | ---- | ---- |
| ウィンドウ(サイドバーと帯) | `windowTranslucency` | 45 | 0〜100 | 5 | 0 は不透明、100 は色を重ねない(すりガラスだけ) |
| ターミナルの背景 | `terminalTranslucency` | 20 | 0〜80 | 5 | 0 は不透明の黒(M4.6 までの見た目) |

- 値は「透過の度合い(%)」の整数。既定のあいだは `state.json` に書かない。キーが無い・数でないときは既定、範囲の外は端に留め、5 の倍数でない値は近い 5 の倍数に丸める。どの場合も `state.json` を退避しない。`schemaVersion` は 1 のまま
- ウィンドウの既定 45 は、M4.6 までの見た目(ライトの地の不透明度 0.55、ダーク 0.5)と同じになる値
- ターミナルの既定を 20 にしたのは、本人が「透けてほしい」と求めたため。上限を 80 にしたのは、文字が読めなくなるのを避けるため
- `arin_core::layout::translucency`(`TranslucencyTarget { Window, Terminal }`、`Translucency`)、`Workspace::step_translucency(target, delta: i32) -> bool`。`delta` は刻みの数でなく % の差分(▲ は +5、▼ は −5。Home・End は範囲の幅ぶん)。規則が 5 の倍数に丸めて端で留める
- 写し `AppSnapshot.translucency = { window: {value,min,max,defaultValue,step}, terminal: {…} }`
- コマンド `step_translucency({target, delta})`。「既定に戻す」は文字の大きさと透過の両方を戻す。コマンド `reset_font_sizes` を `reset_appearance`(`Workspace::reset_appearance`)に替える

### 2. 画面への当て方

- ウィンドウ: `:root` の `--color-window-bg` の不透明度を値から決める。ライトは `1 − t/100`、ダークは `1 − t/100 − 0.05`(0 で留める)。色の RGB は今のまま。計算は `src/logic/appearance/` の純粋な関数に置き、`src/ui/design/` が `:root` に当てる(`interfaceMetrics` と同じ分け方)
- ターミナル: xterm.js を `allowTransparency: true`、テーマの `background` を完全な透明にし、置き場所の地 `--color-terminal-bg`(黒)の不透明度を `1 − t/100` にする。値が変わっても xterm.js には何も送らない(CSS の変数だけが変わる)
- アプリが指定した背景色(色付きのセル)は不透明のまま。選択の色・カーソルは今のまま
- ブラウザ(Playwright)では窓の向こうが無いので、半透明の黒がページの地に重なって見える。破綻しない

### 3. 設定画面

- 「文字の大きさ」の下に「透過」のまとまりを足し、「ウィンドウ」「ターミナルの背景」の 2 行を置く。部品は文字の大きさと同じステッパー(`role="spinbutton"`)を使い、値は「45%」のように出す
- testid は `translucency-row-window`・`translucency-row-terminal`
- 「既定に戻す」は 4 つの値がすべて既定のとき無効

### 4. タイルの番号キー

- コマンド `view.focus-tile-1`〜`view.focus-tile-9`、既定のキー `Cmd+1`〜`Cmd+9`、受け口はメニューの項目。表は 23 行から 32 行になる。「表示」メニューの末尾に区切りを置き、「タイル 1 にフォーカス」〜「タイル 9 にフォーカス」を並べる
- 番号は**表示中のページの中の並び順**(左上が 1。ページを送ると付け直る)。`Workspace::focus_tile_at(position: usize) -> bool`(1 始まり)
- タブ表示のとき・その番号のタイルが無いときは何もしない(キーはターミナルに渡さない)。拡大中に押すと、拡大を解かずにそのタイルへフォーカスを移す…のではなく、**拡大中は何もしない**(見えていないタイルへ移ると迷うため)
- 番号の札: タイル表示のとき、各タイルのターミナルの置き場所の右上に「#1」〜「#9」を半透明で重ねる。クリックを受けない(`pointer-events: none`)、読み上げには出さない(タイトルで足りる。`aria-hidden`)。拡大中は出さない。文字は等幅の数字、画面の文字のトークンに追従する
- 番号の札の文字はキーの表示ではない(キーを替えても「#1」のまま)ので、表から引かない
- 予約のキーの一覧に ⌘1〜⌘9 が入っていれば外す。設定ファイルの見本に 9 行を足す

### 5. Shift+Enter の改行

- ターミナルにフォーカスがあるとき、Shift+Enter(ほかの修飾キーなし、IME の変換中でない)は `ESC` + `CR`(`\x1b\r`)を送る。Claude Code・Codex などの入力欄は、これを「改行」と読む(iTerm2・VS Code の `/terminal-setup` が入れる設定と同じ並び)
- 判定は `src/logic/keys/` の純粋な関数、送るのは `XtermEngine`(`terminal.input`)。⌘⇧Enter(拡大)など修飾キーつきは対象外で、表の扱いのまま
- 表には載せない(ターミナルに渡す文字の決まりで、コマンドではない)。素の zsh(既定のキーの割り当て)では `^[^M` が `self-insert-unmeta` なので、実行されずに改行が入る(複数行の入力になる。レビューの指摘で直した。実機では未確認)

## 却下した案

| 案 | 理由 |
| -- | ---- |
| 透過をスライダーで出す | 設定画面の部品を 1 種類に保つ。5% 刻みのステッパーで足りる |
| ターミナルの既定を不透明のまま | 本人が透けることを求めた |
| ⌘1〜9 をタブ表示ではタブの切替に使う | 求められていない。あとから足せる(同じキーに 2 つの意味を持たせる規則が要る) |
| Option+Enter で改行 | `macOptionIsMeta` を有効にすると JIS 配列の Option の文字入力が壊れる |

## 受け入れ基準(仮。AC-G)

| AC | 受け入れ基準 |
| -- | ------------ |
| AC-G01 | 設定画面に「透過」の 2 行があり、▲▼ で 5% ずつ変わり、端で無効になる。Rust も範囲で留め、5 の倍数に丸める |
| AC-G02 | ウィンドウの透過を変えると `--color-window-bg` の不透明度がすぐ変わる(ライト `1 − t/100`、ダーク `1 − t/100 − 0.05`)。既定 45 で M4.6 と同じ値 |
| AC-G03 | ターミナルの透過を変えると `--color-terminal-bg` の不透明度がすぐ変わり、xterm.js の地は透明。0 で不透明の黒。タブ表示とタイル表示の両方で効く。シェルは続く |
| AC-G04 | 透過の値は再起動しても残る。既定は書かない。壊れた値は既定・端・丸め。退避しない。版 1 のまま |
| AC-G05 | 「既定に戻す」で文字の大きさ 2 つと透過 2 つが既定に戻る。すべて既定なら無効 |
| AC-G06 | タイル表示で ⌘1〜⌘9 を押すと、表示中のページのその番号のタイルにフォーカスが移る。無い番号・タブ表示・拡大中は何もしない。キーはターミナルに渡らない |
| AC-G07 | タイル表示の各タイルの右上に「#1」〜が半透明で出る。ページを送ると付け直る。クリックはターミナルに届く。拡大中とタブ表示では出ない |
| AC-G08 | `settings.toml` で `view.focus-tile-N` のキーを替えられる。メニューの表示が表から出る。見本に 9 行がある |
| AC-G09 | ターミナルで Shift+Enter を押すと `\x1b\r` が PTY に送られ、Enter は `\r` のまま。IME の変換中と修飾キーつきは対象外 |
| AC-G10 | 既存のテストは、理由のある書き換え(表の行数 23→32、`reset_font_sizes`→`reset_appearance`、ターミナルの地の色)だけで通る |

## 影響

- ADR-010 の「ターミナルの置き場所は不透明(黒)のまま」を、この ADR の 1・2 で改める
- ADR-013 の `reset_font_sizes` を `reset_appearance` に替える
- 表の行数 23 を前提にしたテストと文書(`default-shortcuts.test.mjs`、`client.test.ts`、`app_menu.rs`、docs)を 32 に直す
