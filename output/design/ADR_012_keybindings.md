## コンテキスト

本人は「ショートカットの設定もしくは説明はあるの?」と尋ね、選択肢(一覧を見られる画面 / ⌘1〜⌘9 で切替 / キーを変えられる設定)から「キーを変えられる設定」を選んだ。M3・M4 のあとに作る。PRD に無い要件で、FR と AC は PRD に無い(PRD への反映は本人の了承が要る)。

M3・M4 で作った土台:

- 残っている直書き: `src/ui/terminals/TabBar.tsx:157-158` の `aria-keyshortcuts="Meta+T"` と `title="新規ターミナル(⌘T)"`
- 状態ファイルの扱い(手本): 状態フォルダは `AppPaths`(`crates/arin-core/src/paths/app_paths.rs`。`ARIN_STATE_DIR` で差し替え)、読み書きのポートは `StateFilePort`、実装は `arin-platform/src/storage/state_file.rs`、読めないときは `src-tauri/src/persistence.rs` が退避して空で始め、写しの `notice` で 1 行知らせる(`src/ui/shell/NoticeBar.tsx`)

設計書が決めていること: 設定ファイルは `~/Library/Application Support/Arin/settings.toml`(§6.2)。書くのは人間だけで、アプリは読むだけ。保存を検知して読み直す(§1.3 #10)。未知のキーは無視、範囲外の値は既定値に戻して理由を表示、構文エラーのときは直前の値を保ちエラーを表示する(§7.2)。`arin-core` の依存は `serde`・`serde_json`・`thiserror`・`ts-rs` だけ(§3.1。`scripts/check-boundaries.mjs` の `CORE_ALLOWED_DEPENDENCIES` が検査する)。

## 判断

### 1. 置き場所と名前: 状態フォルダの `settings.toml`。ほかの設定と同じファイルに節で分ける

- **推奨(A)**: `<状態フォルダ>/settings.toml`。既定は `~/Library/Application Support/Arin/settings.toml`(§6.2・C-01b のとおり)。`ARIN_STATE_DIR` で状態フォルダを差し替えたときは、**差し替えたフォルダの `settings.toml` だけを読む**(本物の設定ファイルを読まない。テストとスモークはこれで一時フォルダに閉じる)。パスは `AppPaths` に `settings_file()` を足して決める(環境変数を読むのは今までどおり `launch.rs` だけ)
- B: `~/.config/arin/settings.toml`(dotfiles で管理しやすい)。設計書 §6.2 と食い違い、差し替えの指定がもう 1 つ要る。採らない
- C: 設定ファイルの場所だけを差し替える環境変数 `ARIN_SETTINGS_FILE` を足す。テストの閉じ込めは A で足り、環境変数を増やす理由が無い。採らない
- 1 つのファイルに節(TOML の表)で分ける。M4.5 は `[shortcuts]` だけを読む。T56(M6)が `[terminal]`(フォント・配色・スクロールバック)・`[tree]`(移動の確認・目印の時間)・`[notifications]` を足す(§6.2 の `terminal.font_size` は `[terminal]` の `font_size`)。M4.5 では `[shortcuts]` 以外の節は黙って無視する(§7.2「未知のキーは無視」。T56 の節を先に書いても M4.5 の版が知らせを出さない)
- シンボリックリンクの `settings.toml`(dotfiles の管理でよくある形)は、リンクの先を読む。読むだけなので先の場所は問わない【仮定】。ただし 5 の監視はリンクの先の変更を拾えない(6 の説明に書く)

### 2. 書式: `[shortcuts]` の下に「コマンドの ID = キーの文字列」。変えたい行だけを書く

```toml
[shortcuts]
"terminal.new-tab" = "Cmd+Shift+T"
"tree.new-file" = "Cmd+Alt+N"
```

- 節の名前: **推奨(A)** `[shortcuts]`(`arin-core/shortcuts`・コマンドの型 `ShortcutCommandId` と同じ語で、計画の T63 の (3) の案とも同じ)。B: `[keys]`(短いが、TOML の「キー」と紛れる)。C: `[keybindings]`。【仮定】(A で進める。変えるのは定数 1 つ)
- 値は `KeyChord::parse` が読める文字列(1 の書式。正規の書式でなくてよい。`"shift+cmd+t"` も `Cmd+Shift+T` と同じ)
- コマンドの ID は `ShortcutCommandId::as_str` の文字列(大文字・小文字を区別する)。ID は `.` と `-` を含むので TOML では引用符で囲むのが正しい書き方。引用符を付け忘れた `terminal.new-tab = "Cmd+T"` は TOML では入れ子の表(`terminal` の下の `new-tab`)になるので、`[shortcuts]` の下の入れ子の表は 1 段だけ `.` でつないで同じ ID として読む(`[shortcuts.terminal]` の下の `new-tab` も同じ)【仮定】。2 段以上の入れ子は 3 の「読めない行」
- **書かなかった行は既定のキー**。既定に戻すには行を消す(または先頭に `#` を付ける)。ファイルが無いときは全部既定で、知らせを出さない
- 同じ ID を 2 度書くのは TOML の構文エラー(TOML は同じキーを許さない)なので、3 の「ファイル全体」の扱いになる。引用符の有無だけが違う 2 行(`"terminal.new-tab"` と `terminal.new-tab`)は、TOML としては別のキーなので読めてしまう。この場合は「同じコマンドを 2 度書いた」として**両方を使わず既定に戻す**【仮定】
- **割り当てを外す書き方【要確認】**:
  - **推奨(A)**: M4.5 では入れない。空の文字列 `""` は「読めないキー」として、その行を既定に戻して知らせる。理由: 外せるようにすると表の行が「キーを持たない」を許す形(`accelerator` を `Option` にする)に変わり、生成する型・画面の振り分け・ラベル・メニューの組み立てをまとめて直すことになる。M4.5 の範囲では「別のキーに替える」で足りる。いまの `""` は「読めない」なので、あとで「外す」の意味を足しても、前に書いた設定ファイルの意味は変わらない(知らせが消えるだけ)
  - B: `""` で外す。`menu-item` の行は項目を残してキーだけ無くす。⌘W を誤って押してタブを閉じたくない、などに効く。表の型の変更が T64a・T64c・T65e に広がる(上の理由)。なお Tauri の `MenuItem::set_accelerator(None)` は macOS ではキーを消さない(5 の「確かめたこと」)ので、B でもメニューは作り直す
  - C: 専用の値 `"none"`。B と同じ重さで、書き方を 1 つ覚える必要がある

### 3. 検査と失敗のときの扱い(安全側)

**行ごとの問題は、その行だけ既定に戻し、残りの行は使う。問題は画面に 1 行で知らせる**(§7.2 の「範囲外の値は既定値に戻して理由を表示」と同じ考え方)。規則は `arin-core/shortcuts` の純粋な関数に置き、入出力を持たない(T64a)。

| # | 問題 | 扱い | 根拠 |
| - | ---- | ---- | ---- |
| 1 | 値が文字列でない(数・真偽・配列・2 段以上の表) | その行を既定に戻す。知らせる | §7.2 |
| 2 | キーの文字列を読めない(`KeyChord::parse` の失敗。空の文字列を含む) | 同上。理由は `KeyParseError` の種類(空・空の要素・知らない要素・修飾キーの重なり・キーが無い・キーが 2 つ・キーが最後でない) | `key.rs` |
| 3 | 知らないコマンドの ID | 無視する(どの行にも当てない)。**書き間違いに気づけるよう知らせる** | §7.2 は「未知のキーは無視」。無視だけだと、綴りを間違えた人がなぜ効かないか分からない |
| 4 | 変えられないコマンド: `edit.cut`・`edit.copy`・`edit.paste`(受け口が「編集」の標準の項目) | 無視して知らせる(「変えられません」)。**【要確認】** | 標準の項目のキーは muda が決め、表のキーを付けられない(`menu.rs:10-12`)。変えるには自前の項目に替え、WKWebView の `cut:`・`copy:`・`paste:` の働き(画面の cut・copy・paste イベント)を自前で作り直す必要があり、ターミナルとツリーのコピーの振り分け(`clipboardRouting.ts`)に響く。⌘C・⌘X・⌘V を変えたい人は少ない |
| 5 | 受け口を変える書き方 | 受け口は設定では変えさせない(コマンドごとに既定の表の受け口に固定)。値はキーの文字列だけなので、書く場所が無い | 受け口を変えると、ツリーのキーがターミナルの入力を奪うなど、振る舞いが変わる |
| 6 | OS やアプリの標準の項目が先に取るキー(予約のキー。下の一覧) | その行を既定に戻す。知らせる(「macOS が使うキーです」) | メニューのアクセラレータより先に OS が取る、または標準の項目とぶつかって、割り当てても効かない |
| 7 | 受け口が `menu-item` の行で、`Cmd` を含まないキー | その行を既定に戻す。知らせる(「⌘ を含むキーにしてください」) | メニューのアクセラレータは WKWebView より先に OS が受ける(フォーカスによらない)。修飾キーの無い文字・`Shift` だけ・`Ctrl` だけ(⌃C などシェルのキー)・`Alt` だけ(⌥ で打つ文字)を割り当てると、ターミナルで打てなくなる |
| 8 | 受け口が `screen` の行で、`Cmd` を含まず、修飾キーの無い `Enter`・`Space`・`Backspace`・`Delete` のどれでもないキー | その行を既定に戻す。知らせる | 画面で受けるキーはツリーにフォーカスがあるときだけ効く(既定の `tree.rename` = `Enter` は、このため許している)。文字・数字・記号・`Shift` だけの組はツリーでの文字の入力と紛れ、矢印・`Tab`・`Escape` は移動と取り消しに使う【仮定】 |
| 9 | 同じキーの二重の割り当て(設定の行どうし、または設定の行と既定の行) | 重なりに関わる**設定の行**をすべて既定に戻す。戻したことで新しい重なりができたら、無くなるまで繰り返す(既定の表は重ならないので必ず止まる)。知らせる(「Cmd+T は terminal.new-tab が使っています」) | 表全体でキーを重ねない(`from_bindings` の規則)。どちらか一方を勝たせると、書いた順や ID の順で結果が変わる。「関わる設定の行をすべて戻す」は順によらず決まる。キーを入れ替えたいときは両方の行を書けばよい |
| 10 | 同じコマンドを 2 度書いた(2 の引用符の有無だけが違う 2 行) | 両方を使わず既定に戻す。知らせる | どちらを採っても書いた人の意図と違いうる |

予約のキー(6。`arin-core/shortcuts` に定数の一覧で持つ【仮定】。本人が足し引きできる):

- アプリ名のメニューの標準の項目: `Cmd+H`(隠す)、`Cmd+Alt+H`(ほかを隠す)
- アプリの切り替えと入力: `Cmd+Tab`、`Cmd+Shift+Tab`、`Cmd+Space`、`Ctrl+Space`、`Cmd+Ctrl+Space`(絵文字と記号)、`Cmd+Alt+Space`
- 画面の取り込み・ロック・強制終了: `Cmd+Shift+3`、`Cmd+Shift+4`、`Cmd+Shift+5`、`Cmd+Ctrl+Q`、`Cmd+Alt+Escape`
- ウィンドウと操作スペース: `` Cmd+` ``、`Ctrl+ArrowUp`、`Ctrl+ArrowDown`、`Ctrl+ArrowLeft`、`Ctrl+ArrowRight`
- 一覧に無いキー(本人が「システム設定」で足した OS のショートカットなど)は検査できない。効かないときの確かめ方を 6 の見本に書く
- `Cmd+Q`(終了)は予約にしない。`app.quit` の既定のキーで、表の行なので 9 の重なりの検査で守られる。`app.quit` 自体のキーは変えてよい(7 の規則で ⌘ を含む)
- 既定の表は予約のキーを使わない(テストで確かめる)

**ファイル全体の問題**は、起動時は既定の表、動作中(5 の読み直し)は**直前に使っていた表のまま**にして知らせる(§7.2「構文エラーのときは直前の値を保つ」。起動時の「直前」は既定)。

| 問題 | 知らせに出すもの |
| ---- | ---------------- |
| TOML として読めない(構文エラー) | 行と列だけ(例「設定ファイルの 12 行 5 列目を読めないため、ショートカットは既定のままです」) |
| UTF-8 でない・大きすぎる(1 MiB を超える【仮定】)・フォルダなどファイルでない・権限が無くて読めない | 理由の種類だけ |
| `[shortcuts]` が表でない(`shortcuts = 1`) | 節の名前だけ。ほかの節(T56)は読む |
| ファイルが無い | 知らせない(既定のまま) |

**設定ファイルは退避しない・書き換えない・消さない**(人が手で書くファイルで、アプリは読むだけ。§1.3 #10。`state.json` の退避の仕組みは使わない)。唯一の例外は 6 の「設定ファイルを開く…」で、**ファイルが無いときだけ**見本を新しく作る(同じ名前があれば作らない=上書きしない。0600)。

知らせと診断の決まり:

- 画面には 1 行(`NoticeBar` と同じ形。長い文は省略し、全文はツールチップ)。標準エラーには `[arin:settings]` を頭に、問題 1 つにつき 1 行
- 出すのは**コマンドの ID・キーの文字列・行と列・理由の種類だけ**。設定ファイルの中身(行の全文)、TOML のクレートの失敗の文言(該当行の抜粋を含むことがある)、絶対パスは出さない(§12)。行と列はクレートが返す位置(バイトの範囲)から自前で数える
- 知らせに出す ID とキーの文字列は、書いた人の文字列なので、制御文字を除き、64 文字で切る【仮定】
- 状態ファイルの知らせ(写しの `notice`)とは別に持ち、両方あれば 2 行出す(片方を閉じても他方は残る)

### 4. TOML を読むクレートと置き場所

- **解析は `arin-platform` に置く**(`storage/settings_file.rs` の `FsSettingsFile`=読むだけのポートの実装と、TOML を「節の名前・キー・値の種類」の素朴な形にする関数)。`arin-core` には**文字列の対**(コマンドの ID → キーの文字列。値が文字列でない行は「文字列でない」の印)と、ファイル全体の結果(無い / 読めない理由 / 構文エラーの行と列)だけを渡す。`arin-core` の依存は増やさない(§3.1、境界検査)
- クレートの候補:
  - **推奨(A)**: `toml`。`Cargo.lock` を grep して確かめた範囲では、`toml 1.2.1+spec-1.1.0` が `tauri-utils 2.10.2` の依存として既に載っている(`tauri-utils` の `Cargo.toml` は `toml` を `>=0.9, <=1`、`features = ["parse"]` で、必須の依存として持つ)。ほかに `toml 0.8.2`(`system-deps` の依存)も載っている。ADR-009 にならい、Tauri が引き込んでいる版にそろえて新しいクレートを増やさない
  - B: `toml_edit`・`toml_parser`(下の層。Lock に載っている)。コメントを保ったまま書き換える用途の部品で、読むだけの M4.5 には要らない
  - C: 自前の解析。TOML の仕様(引用符・入れ子の表・複数行の文字列)を正しく読むのは重く、読み違いが安全に響く。採らない
- **実装のとき(T65a)に確かめること**(この環境ではコマンドを動かせないので、版・公開日・ライセンス・依存の数は書かない。推測の数字を書かない):
  - `cargo tree -i toml --target aarch64-apple-darwin` で、`toml 1.2.1+spec-1.1.0` が macOS 向けの依存の木に入っているか(入っていれば同じ版を `=` で固定する)
  - `cargo info toml`・crates.io で、その版の公開日(公開から 2 週間未満の版を避ける。ADR-003)とライセンス
  - 使う機能(features)を最小にし、`tauri-utils` が既に有効にしている機能の範囲に収まるか。収まらず依存が増えるなら、その数を ADR-012 に追記する
  - 足したあとも `cargo tree -i reqwest --target aarch64-apple-darwin` が空のまま(通信のクレートが増えない。NFR-008)
- 決めた版と確かめた結果は、T65a で本 ADR の末尾に追記し、`project-config.md` §2 と `docs/project.md` の技術スタックに T66b で反映する

### 5. 反映のタイミング【要確認】

| 案 | 中身 | 重さ | 使い勝手 |
| -- | ---- | ---- | -------- |
| A | 起動時だけ読む | 軽い(T65b だけ) | **キーを試すたびにアプリを再起動する必要があり、再起動すると動いているシェルがすべて終わる**(N3。プロセスは保存しない)。Claude Code などを動かしたままでは試せない |
| **B(推奨)** | 状態フォルダを監視し、`settings.toml` が保存されたら読み直してメニューと画面を差し替える | 中(T65c が増える。監視のスレッド 1 本、メニューの作り直し、画面へのイベント) | 保存するとすぐ効く。設計書 §1.3 #10「保存を検知して読み直す」と同じ |
| C | 起動時に読み、メニューの「設定を読み直す」で読み直す | 小〜中(監視は要らないが、作り直しと画面へのイベントは B と同じ) | 保存のあとに 1 操作要る。シェルは残る |

推奨は B。理由: A は「試すたびにシェルが消える」ので、ターミナルのアプリでは実用にならない。C との差は監視のスレッドだけで、監視は M3 の `notify`(`arin-platform/src/watch/fsevents.rs` の `FsEventsWatcher`。束ねる待ち時間 0.2 秒)をそのまま使える。B を採らない場合も、作り直しと画面へのイベントは C と共通なので、T65c を「メニューの項目で読み直す」に替えるだけで済む。

B の中身(T65c):

- `WatcherPort` で**状態フォルダ**を監視し(エディタは一時ファイルに書いて改名して保存することが多いので、ファイルではなくフォルダに張る)、届いたパスの名前が `settings.toml` のときだけ読み直す。`state.json` の書き込みの知らせは捨てる。状態フォルダが無ければ 0700 で作ってから張る(`FsStateFile` と同じ権限。設定ファイルは作らない)
- 読み直した結果が今の表と同じなら何もしない。違えば管理状態の表を差し替え、メニューを作り直し、画面へイベントで新しい表と知らせを送る
- シンボリックリンクの先の変更は拾えない(1)。そのときは保存のあとにリンク自体を触る(`touch`)か再起動する、と見本に書く【仮定】

確かめたこと(Tauri 2.12.5・muda 0.20.0 のソース。`~/.cargo/registry/src/`。動かしてはいない):

- `tauri::menu::MenuItem::set_accelerator`(`tauri-2.12.5/src/menu/normal.rs:110-117`)はあるが、文字列を読めなければ黙って `None` にする(`.parse().ok()`)。muda の macOS の実装(`muda-0.20.0/src/platform_impl/macos/mod.rs:320-342`)は、`None` のときキーを消さずに何もしない
- `AppHandle::set_menu`(`tauri-2.12.5/src/app.rs:981-1017`)で、アプリ全体のメニューを丸ごと差し替えられる(macOS ではメインスレッドで `init_app_menu` を呼ぶ)

## 検討した代替案

- 設定の画面(キーを押して割り当てる画面): N5 に触れ、本人の選択(設定ファイルで変える)とも違う。採らない
- 問題のある行が 1 つでもあれば、ファイル全体を無視する: 1 行の書き間違いで全部の変更が消える。どの行が悪いかを知らせれば、行ごとに戻すほうが安全で分かりやすい。採らない(ファイルとして読めないときだけ全体を扱う)
- 読めない設定ファイルを `state.json` と同じく退避する: 人が手で書いたファイルを、アプリが勝手に動かすことになる。§1.3 #10 に反する。採らない
- 重なりでは設定の行を勝たせ、既定の行のほうを外す: 外された既定のコマンドのキーが無くなり(表はキーを必ず持つ)、2 の「外す書き方」と同じ問題になる。採らない

## ファンクションキーの追加と、ツリーの Enter・名称変更の既定(2026-11-21。本人の決定)

本人の要望「Enterで、フォルダだったら展開。マークダウンだったらエディタ。」を受けて、次のとおり改めた。選択肢は本人が選んだ。

- **キーの書式に `F1`〜`F12` を足した**(Rust の `KeyChord::parse` と画面の `parseAccelerator` の両方。大文字・小文字を区別しない)。`F13` 以上は今までどおり読めない
- **検証の規則 #8 を広げた**: 画面の行(ツリーのキー)は、⌘ を含むキーか、修飾キーの無い `Enter`・`Space`・`Backspace`・`Delete`・`F1`〜`F12`。メニューの項目の行(#7)は今までどおり ⌘ が要る(`Cmd+F5` は書ける)
- **名称変更(`tree.rename`)の既定を `Enter` から `F2` に移した**。右クリックのメニューの「名称変更…」は今までどおり
- **ツリーの Enter は「開く」**(ダブルクリックと同じ): フォルダは開閉、`.md`・`.markdown` はエディタ、ほかのファイルは既定のアプリ(本人が選んだ)。表には載せず、表に Enter の割り当てが無いときだけ効く(設定で `"tree.rename" = "Enter"` と書けば、以前の動きに戻せる)
- ツリーの矢印キー(上下で選択、右で開く、左で閉じる・親へ)も表に載せない。修飾キーの無い矢印は表に書けないので(#8)、取り合いは起きない
- 「読めない設定の例」に `tree.rename = F2` を使っていたテストとスモークは、`F13` に替えた

影響: これまで `settings.toml` に `"tree.rename" = "F2"` と書いて既定に戻されていた人は、そのまま F2 が効くようになる。ほかのコマンドに `F2` を割り当てることは今まで出来なかったので、既定の変更で新しく重なる行は無い。

注意: Mac の内蔵キーボードの既定では、F1〜F12 は明るさ・音量などの操作になり、F2 として押すには fn を一緒に押す(「システム設定 → キーボード → キーボードショートカット → ファンクションキー」で標準のファンクションキーに替えられる)。fn を押したくないときは、`settings.toml` で `"tree.rename"` を別のキーにする。
