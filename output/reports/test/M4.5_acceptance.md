## 完了前のレビューで見つけて直したもの

- 知らない ID の行が大量にある設定ファイル(1 MiB の上限の中で約 17 万行)で、重複の判定が行数の 2 乗になり、起動が数十秒止まりうる。集合で判定するようにした
- 上の場合に、知らせの 1 行と標準エラーが数 MB になる。知らせに並べる問題は 8 件まで、標準エラーは 50 件までにして、残りは「ほか N 件」にまとめた
- 知らせに出す ID とキーの文字列に、文字の向きを変える制御文字(U+202E など)が残り、知らせの見た目の並びを入れ替えられた。除くようにした

## 判断が要る点・残っている問題

| 項目 | 状態 |
| ---- | ---- |
| `toml 1.2.1` の版 | 公開が 2026-11-06 で「2 週間未満の版は選ばない」に当たるが、Tauri 経由ですでに組み込まれている版なので、本人が 2026-11-16 に例外を認めた(ADR-012 の末尾)。`Cargo.lock` の差分は依存の並びの 1 行だけ |
| F キー(`F2` など) | 設定の書式で読めない(「キーを読めません」になる)。ADR-012 に F キーの扱いは書かれていない。使えるようにするかは本人の判断 |
| 設定の知らせが長いとき | 1 行に収まらない分は「…」で省略される(問題が 9 件以上なら「ほか N 件」)。全文は標準エラー。折り返すかは実機で見て決める |
| 知らせの文の中のキーの書き方 | 知らせは設定ファイルの書式(`Cmd+W`)で出る。メニューの表示(⌘W)とは違う |
| その場で上書きする保存 | エディタが設定ファイルをその場で書き換えると、書きかけの中身を読んで一瞬だけ既定のキーに戻り、次の知らせで正しいキーに戻ることがありうる(一時ファイルに書いて改名する保存では起きない) |
| 監視を張る前の保存 | 起動時に読んでから監視を張るまでの間に保存された分は、次の保存まで拾わない |
| シンボリックリンクの設定ファイル | リンクの先を保存しても反映されない(見本に書いてある。リンク自体を触るか再起動) |
| 「設定ファイルを開く…」の置き場所 | アプリ名のメニューの先頭(計画どおり)。macOS の慣習は「…について」の下だが、いまは「…について」の項目が無い |
| ふつうのファイルでない・実行できる設定ファイル | 開かずに Finder で表示して知らせる(ツリーの「開く」と同じ規則。計画に無い追加) |
| 取り直しの失敗(画面) | 続けて届いた `settings-changed` のうち最新の取り直しだけが失敗すると、次の保存まで画面の表が古いままになる(レビューの SHOULD。Tauri のコマンドの失敗は通常起きないので直していない) |
| 監視のスレッド | 中で panic すると黙って止まり、以後の保存を拾わない(レビューの CONSIDER。直していない) |
| BOM 付きの UTF-8 | 未確認。`toml` が BOM を受け付けなければ「1 行 1 列を読めない」になる |
| テストの作法 | `settings_watch.rs` が本物の `MacDesktop` を組み立てに渡し、2 つのテストが一般のペーストボードの型を作っている(どちらも呼ばれない。照合の SHOULD。直していない) |
| `e2e/settings.spec.ts` の見本の知らせ | 偽の応答の文が、実アプリの理由の文と違う(テストは通る) |
| PRD への反映 | FR の追加と AC-K01〜K10 の採否は本人の判断(T66d) |

## 本人に確かめてほしいこと(T66c の (1)〜(10))

`npm run app` で作った `target/aarch64-apple-darwin/release/bundle/macos/Arin.app` を Finder から開く。設定ファイルは `~/Library/Application Support/Arin/settings.toml`。

1. ⌘, で見本が既定のアプリで開き、書き方が読んで分かる(AC-K08)。アプリ名のメニューに「設定ファイルを開く…」と ⌘, が出ている
2. 見本の `[shortcuts]` の下に `"terminal.new-tab" = "Cmd+Shift+T"` を書いて保存すると、メニューバーの「新規タブ」が ⇧⌘T になり、⇧⌘T で開き、⌘T では開かない(AC-K01・K07)
3. `"tree.new-file" = "Cmd+Alt+N"` を書いて保存すると、ツリーの右クリックのメニューの表示とキーが替わる(AC-K02)
4. 保存しても、動いているシェル(Claude Code など)が続いている(AC-K07)
5. 読めない行(`"tree.rename" = "F2"`)、予約のキー(`"terminal.new-tab" = "Cmd+H"`)、重なり(`"terminal.new-tab" = "Cmd+W"`)を書くと、その行だけ既定に戻り、知らせが 1 行で読める(AC-K04)
6. 構文を壊して(引用符を閉じないなど)保存すると、直前のキーのまま、知らせに行と列が出る(AC-K05)
7. 行を消して保存すると既定のキーに戻り、知らせが消える(AC-K03)
8. 替えたキーが US と JIS の配列で効き、ターミナルに文字として渡らない。替える前のキーはターミナルに渡る(AC-K06)
9. 知らせの見た目(ライトとダーク、すりガラスの上。2 行出たとき)。自動テストの画像は `testreport/e2e/settings/`
10. ADR-012 の決定のままでよいか、PRD への反映(FR の追加・AC-K の採否)をどうするか

## 誰も確かめていないこと

- 実機のメニューバーに出るキーの表示と、実際にキーを押したときの動き(自動テストは表とキーの文字列まで)
- 本物の既定のアプリと Finder で設定ファイルが開くこと(自動テストは偽のデスクトップ)
- `.toml` を開けるアプリが無い Mac での挙動
- 実際のエディタ(その場で上書きする保存をするもの)での保存の検知
