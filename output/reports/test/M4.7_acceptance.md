## 判断が要る点・残っている問題

| 項目 | 状態 |
| ---- | ---- |
| 素の zsh での Shift+Enter | 既定のキーの割り当てでは、実行されずに改行が入る見込み(レビューの指摘。実機では未確認) |
| 番号の札の位置 | ターミナルの 1 行目の右端に重なる。右寄せのプロンプトや TUI の右上の文字が読みにくくなりうる |
| 番号の札の字体 | 画面の字体で数字の幅だけそろえている(等幅の字体ではない) |
| 反転表示・選択・カーソル | 地を透明にした状態での見え方を画像で確かめていない |
| Shift+Enter を設定で別のコマンドに割り当てたとき | 改行の判定が表より先なので、割り当ては効かない |
| タブ表示の ⌘1〜9 | 何もしない(タブの切替には使っていない) |
| 設定画面を開いたままの ⌘1〜9 | 後ろのタイルのフォーカスが替わる(⌘T などと同じ扱い) |
| 範囲と既定 | ウィンドウ 0〜100(既定 45)、ターミナル 0〜80(既定 20)。変えるかは本人の判断 |

## 本人に確かめてほしいこと

1. 設定画面(⌘,)の「透過」の「ウィンドウ」で、サイドバーと上部の帯の透け具合が変わる(ライトとダーク)
2. 「ターミナルの背景」で、ターミナルの背景が透ける。文字が読める。0% で不透明の黒に戻る
3. 再起動しても残る。「既定に戻す」で文字の大きさと透過が戻る
4. タイル表示で ⌘1〜9 がその番号のタイルにフォーカスし、右上の「#1」〜が邪魔にならず読める
5. Claude Code の入力欄で Shift+Enter が改行になる。日本語入力の変換中の Shift+Enter がおかしくない
6. ADR-014 の決定(範囲・既定・拡大中は何もしない)のままでよいか
